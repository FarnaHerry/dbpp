# db++ v0.4.2

补丁版本发布：将表元数据探测与行定位抽象为通用多方言机制，修复 MySQL 等非 SQLite 数据库表无法双击内联编辑的问题，支持主键、唯一键、隐藏行标识及无主键表的通用写回。

## 变更与修复

### 通用多方言表标识与内联编辑支持
- **多方言表元数据探测 (`ResolveTableIdentityBlocking`)**：将此前仅针对 SQLite `PRAGMA table_info` / `rowid` 的探测抽象为通用接口，按数据库方言自动补全列类型、`NOT NULL`、默认值、备注与主键/唯一键信息：
  - **MySQL / MariaDB**：通过 `SHOW FULL COLUMNS FROM`（兼容回退 `SHOW COLUMNS FROM`）与 `SHOW INDEX FROM` 解析 `PRIMARY` 主键及多列唯一索引；
  - **PostgreSQL**：通过 `information_schema.columns` 与 `pg_catalog.pg_index` 解析主键与唯一索引；
  - **DuckDB / SQLite / Generic ADBC**：分别通过 `PRAGMA table_info`、`PRAGMA index_list` / `index_info` 及 `information_schema` 探测键信息与列属性。
- **四级行定位策略 (`RowLocatorKind`)**：对普通表按优先级自动解析行定位标识：`PrimaryKey` > `UniqueKey`（优先非空唯一键） > `HiddenRowId`（SQLite/DuckDB `rowid`、PostgreSQL `ctid::text` + `::tid`） > `AllColumns`（无主键表自动回退为非 BLOB 列全列匹配，并在 MySQL `UPDATE` / `DELETE` 语句自动附加 `LIMIT 1`）。
- **目录与 Arrow Schema 主键传播修复**：修复 `EnrichMysqlCatalog` 等目录扫描及 `AdbcPopulateColumnsFromArrowSchema` 中 `PRIMARY` 索引未同步到 `DbObject::primary_key` 与 `NOT NULL` 属性丢失的问题，并统一支持大小写不敏感列名匹配。
- **单元测试补充**：在 `tests/test_adbc_capabilities.cpp` 新增 `PrimaryKey`、`UniqueKey`、`HiddenRowId`、`AllColumns`、MySQL 索引主键提示及视图只读判定校验，CTest 5/5 全部通过。
