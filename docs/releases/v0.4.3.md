# db++ v0.4.3

补丁版本发布：修复多数据库方言下时间/时间戳（`TIMESTAMP`、`DATETIME`、`DATE`、`TIME`）的读取格式、编辑写回归一化、参数绑定与 SQL 字面量生成问题，解决 MySQL 等数据库保存时间字段失败的缺陷。

## 变更与修复

### 多方言时间 / 时间戳读写修复
- **统一 Arrow 时区读取格式 (`AdbcFormatTimestampTz`)**：带时区的 Arrow 时间戳由原先拼接 `" UTC"` / `" <tz>"` 改为输出标准 ISO-8601 UTC（`YYYY-MM-DDTHH:MM:SS[.frac]Z`），无时区时间戳保持 `YYYY-MM-DD HH:MM:SS[.frac]`。
- **共享时间解析器与按方言写回归一化 (`NormalizeTimestampForWrite`)**：
  - 新增 `AdbcParseTimestampInstant`、`AdbcParseNaiveDateTime`、`AdbcParseDateDays`，支持 `YYYY-MM-DD` / `YYYY/MM/DD`、`T` 或空格分隔、可选秒数、时区后缀（`Z`/`UTC`/`GMT`/`±HH:MM`）及秒/毫秒/微秒/纳秒 Unix 时间戳；
  - 区分 **MySQL `DATETIME`**（保持墙上时间不做 UTC 偏移，统一为 `'YYYY-MM-DD HH:MM:SS[.frac]'`）与 **MySQL `TIMESTAMP` / PostgreSQL & DuckDB `TIMESTAMPTZ`**（统一为 ISO-8601 UTC），支持 `"now"`、Unix 时间戳输入及 `DATE` / `TIME` 格式化；
  - 编辑原值为 `NULL` 的单元格时传入空 `raw_original` 避免误判；在异步保存、批量新增与生产模式确认等调用点传递当前会话 `Dialect`。
- **方言感知 SQL 字面量与参数绑定 (`SqlLiteral` / `BuildParameterBatch`)**：
  - `SqlLiteral` 对 MySQL `TIMESTAMP` 自动转为 `FROM_UNIXTIME(<utc_sec>[.<us>])`（不受 `@@session.time_zone` 影响），对 MySQL `DATETIME`、`DATE` 与 PostgreSQL/DuckDB `TIMESTAMPTZ`/`TIMESTAMP`/`DATE` 输出对应方言格式（涵盖 `UPDATE`、`INSERT`、`AllColumns` `WHERE` 条件及 SQL 导出）；
  - `BuildParameterBatch` 支持原生 Arrow `NANOARROW_TYPE_TIMESTAMP`（保留 `time_unit` / `timezone`）与 `NANOARROW_TYPE_DATE32` 参数绑定；对 MySQL 涉及非整型时间列的写操作自动改走安全 SQL 字面量路径。
- **单元测试补充**：在 `tests/test_adbc_capabilities.cpp` 新增第 19 节测试覆盖 MySQL/PostgreSQL 时间类型归一化与 `SqlLiteral` 生成校验，CTest 5/5 全部通过。
