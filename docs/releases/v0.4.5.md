# db++ v0.4.5

补丁版本发布：新增基于操作失败触发的维护性惰性刷新机制，当表、视图或字段在外部被删除或修改导致查询、筛选、提交或设计页报错时，自动同步所属数据库连接目录并清理已失效标签页。

## 变更与修复

### 失败触发的维护性惰性刷新
- **跨方言元数据过期错误识别 (`IsSchemaStaleError`)**：
  - 统一识别 SQLite（`no such table/column/view`）、MySQL / MariaDB（`doesn't exist`、`unknown column/table/database`、`1146` / `1054` / `1049` / `1051`）、PostgreSQL / DuckDB（`does not exist`、`catalog error`、`binder error`）及通用 SQLSTATE（`42S02`、`42S22`、`42P01`、`42703`、`3D000`、`3F000`、`42S01`）缺失/过期对象错误；
  - 明确排除连接断开、语法错误与 `UNIQUE` / `NOT NULL` 等约束冲突，避免误刷新。
- **防并发、防抖与防死循环刷新 (`ScheduleMaintenanceRefresh`)**：
  - 通过 `AdbcSession::refresh_in_flight` 去重并发刷新并设置 3000 ms 冷却窗口（`last_maintenance_refresh_ms`）；
  - 维护刷新更新连接对象目录并关闭已移除表对应的 `Table` / `TableDesign` 标签页（关闭时弹出提示），且不重复重拉当前出错标签页，避免因错误筛选列名触发“报错 → 刷新 → 重查报错”循环。
- **核心失败路径接入**：已接入表格加载/筛选/排序/翻页（`RequestLoadTable`）、表格事务批提交（`RequestCommitTableChanges`）、SQL 控制台读写执行（`ExecuteSqlTabQuery`）及表结构设计页加载与 DDL 执行（`TableDesignPage`）。
- **单元测试补充**：在 `tests/test_adbc_capabilities.cpp` 第 21 节新增多方言缺表/缺列匹配、负向排除及真实 SQLite `DROP` 查询触发测试，CTest 5/5 全部通过。
